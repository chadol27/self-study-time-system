# 스공시 좌석 및 출결 관리 시스템

학생의 좌석과 출결을 Google Spreadsheet와 웹 화면에서 관리하는 시스템입니다.

## 처음 사용할 때

1. 시스템 관리자로부터 대상 스프레드시트와 웹 앱 주소를 받습니다.
2. 스프레드시트를 새로 연 뒤 **스공시 관리 → 시트 초기화 및 검사**를 실행합니다.
3. `학생명단` 시트를 작성하고 **스공시 관리 → 학생 명단 적용**을 실행합니다.
4. 검사 결과에 오류가 있으면 안내된 학번, 좌석번호, 요일과 교시를 확인해 시트 값을 수정합니다.
5. 웹 앱에서 학생 로그인과 교사 로그인이 정상적으로 되는지 확인합니다.

## 학생명단 입력

`학생명단` 시트의 1행은 제목 행이며, 2행부터 전체 학생 정보를 입력합니다.

| 열 | 입력 내용 |
| --- | --- |
| A | 학번 |
| B | 이름 |
| C | 전화번호 뒤 4자리 |

학번과 전화번호 뒤 4자리는 텍스트로 입력합니다. 전화번호 뒤 4자리는 `0123`처럼 앞의 0을 포함한 정확한 네 자리여야 합니다. 명단을 수정한 뒤 **스공시 관리 → 학생 명단 적용**을 실행하면 유효한 학생 정보와 오류를 확인할 수 있습니다.

학생명단은 자정 일일 작업 때도 자동으로 다시 적용됩니다. 평소에는 캐시된 명단을 사용하며, 캐시가 만료되거나 필요한 학번이 캐시에 없을 때만 시트를 다시 읽습니다.

## 명부 입력

`명부` 시트의 1-2행은 제목 행이며, 학생 정보는 3행부터 한 명당 한 행에 입력합니다.

| 열 | 입력 내용 |
| --- | --- |
| A | 학번 |
| B | 좌석번호 |
| C:N | 월-목의 1-3교시 신청 여부 |
| O | 시스템이 자동 생성하는 내부 키 |
| P 이후 | 날짜별 1-3교시 출결 상태 |

이름과 전화번호 뒤 4자리는 `명부`에 입력하지 않습니다. O열은 시스템용이므로 직접 수정하지 않습니다.

### 신청 여부 숫자

`명부` 시트 C:N열에는 각 요일과 교시의 신청 여부를 입력합니다.

| 값 | 의미 |
| --- | --- |
| 빈 값 | 미신청 |
| `0` | 미신청 |
| `1` | 신청 |

`0`, `1`, 빈 값 이외의 값은 입력하지 않습니다.

같은 요일에는 교시가 달라도 두 학생이 같은 좌석을 사용할 수 없습니다. 서로 다른 요일의 좌석 공유는 가능합니다. 충돌 학생은 오류를 해결할 때까지 모든 요일의 교사 좌석에서 제외됩니다.

### 출결 상태 숫자

`명부` 시트 P열 이후의 날짜별 출결 칸에는 다음 값이 표시됩니다.

| 값 | 의미 | 조회 전용 교사 화면 표시 |
| --- | --- | --- |
| 빈 값 | 미래 출결이 아직 확정되지 않았거나 해당 교시 미신청 | 신청 학생은 흰색 신청, 미신청은 회색 |
| `0` | 기존 자료의 미확정 또는 미신청 값으로, 빈 값과 동일 | 빈 값과 동일 |
| `1` | 신청 | 현재 교시 신청이면 흰색, 미신청이면 회색 |
| `2` | 출석함 | 초록색 |
| `3` | 결석함 | 빨간색 |
| `4` | 학생이 미리 등록한 결석 | 주황색 |

출결값은 가급적 웹 앱에서 변경합니다. 시스템이 당일 신청 교시에 기록하는 신청 상태 `1`은 `기록` 시트에 남지 않으며, 학생이나 교사가 직접 변경한 내용만 기록됩니다. 기존 출결값은 변환하지 않고 위의 새 의미로 그대로 해석합니다.

위 색상은 실제 저장값을 나타내는 조회 전용 화면 기준입니다. 오늘 편집 화면은 체크한 학생을 초록색 출석 예정, 해제한 신청자를 빨간색 결석 예정, 해제한 현재 교시 미신청자를 회색으로 표시합니다. 사전 결석 `4`는 주황색으로 유지합니다. 기본 체크와 색상은 저장 완료를 뜻하지 않습니다.

학생 또는 교사가 여러 교시나 여러 결석일을 한 번에 변경하면 출결 셀과 `기록` 시트 행을 범위 단위로 저장합니다. 각 교시의 변경 이력은 기존과 동일하게 별도 행으로 유지됩니다.

## 학생 사용 방법

1. 웹 앱에서 **학생용**을 선택합니다.
2. 학번과 전화번호 뒤 4자리로 로그인합니다.
3. 상단에서 본인의 좌석번호와 월-목 교시별 정기 신청 현황을 확인합니다. 오늘부터 30일 후까지 결석할 날짜 또는 기간을 선택해 등록합니다.
4. 본인이 등록한 사전 결석 날짜를 목록에서 확인하고, 취소할 날짜를 선택해 한 번에 취소할 수 있습니다. **전체 선택** 버튼은 취소 가능한 날짜를 모두 선택하며, 선택 후에는 같은 버튼으로 전체 해제할 수 있습니다. 목록에는 교시를 별도로 표시하지 않습니다.
5. 사용을 마치면 로그아웃합니다. 로그아웃하면 학생 로그인 화면으로 돌아갑니다.

금요일부터 일요일과 `설정` 시트에 등록된 미운영일은 결석 등록 대상에서 자동으로 제외됩니다. 당일 변경은 1교시 시작 시각 전까지만 가능하며, 마감 후 시작일과 종료일은 내일부터 선택됩니다. 교사가 지정한 출석과 결석은 학생이 취소할 수 없습니다. 학생 로그인은 로그인 시점부터 5분간 유지되며 활동해도 연장되지 않습니다. 학생 키와 만료 시각은 현재 페이지의 JavaScript 변수에만 저장되므로 페이지를 새로고침하면 다시 로그인해야 합니다.

## 교사 사용 방법

1. 웹 앱에서 **교사용**을 선택하고 교사 비밀번호를 입력합니다.
2. 날짜와 교시를 선택해 좌석별 출결 상태를 확인합니다. **오늘 운영일만 수정 가능**하며, 과거와 향후 30일 날짜는 조회만 가능합니다.
3. 좌석 본문을 눌러 출석 체크를 켜거나 끕니다. 좌석의 작은 글씨는 저장된 상태에 따라 `신청`, `출석`, `결석`, `결석 예정`, `해당교시 미신청`으로 표시되고, 빈 좌석은 번호만 표시됩니다. 저장된 상태와 저장 예정 상태가 다르면 처음부터 `이전 상태 → 변경 예정 상태` 형식으로 표시하고, 같으면 현재 상태만 표시합니다. 저장을 완료하면 최신 저장 상태명만 표시됩니다. 우측 상단 정보 아이콘은 학생 정보, 월-목 전체 신청 요일과 교시, 현재 저장된 출결 상태를 표시합니다. 모든 교시를 신청한 요일은 `월`, 일부 교시는 `수1-2`, `목1`과 같이 표시됩니다.
4. 상단의 **교사** 입력은 항상 한국 시간 기준 오늘 정보입니다. 좌석 날짜 선택과 관계없이 페이지 로드 때 오늘 저장값을 표시하고, **저장**하면 오늘 행을 만들거나 기존 오늘 행을 수정합니다. 앞뒤 공백은 제거하며, 빈 값도 저장할 수 있고 최대 100자까지 입력할 수 있습니다.
5. 좌석 위 도구 모음의 **저장**으로 체크·해제 상태 전체를 한 번에 반영합니다. 도구 모음에는 **저장**, **전체 선택/전체 해제**만 있고 되돌리기는 없습니다. 전체 선택은 현재 교시 신청자 중 사전 결석 `4`를 제외한 학생만 체크하며 미신청 개별 체크는 유지합니다. 대상 신청자가 모두 체크되면 전체 해제로 바뀌어 미신청 개별 체크까지 해제합니다. 대상 신청자가 없으면 체크가 있을 때 전체 해제, 없으면 비활성화됩니다. 체크가 0명이어도 저장 대상이 있으면 저장할 수 있습니다.
6. 사용을 마치면 로그아웃합니다. 교사 페이지의 **메인**을 눌러 돌아가도 자동으로 로그아웃됩니다.

메뉴나 각 페이지의 메인 링크를 누르면 대상 화면이 표시될 때까지 로딩 안내가 나타납니다. 교사 페이지는 최초 인증과 설정 확인 중 `불러오는 중...`을 표시하며, 좌석 데이터를 불러오는 동안 좌석 선택과 변경 기능을 사용할 수 없습니다.

해당 요일에 한 교시라도 신청한 학생은 모든 교시에 좌석에 표시됩니다. 현재 교시 미신청자도 개별 체크할 수 있습니다. 그 요일에 전혀 신청하지 않은 학생은 아래 별도 미신청자 기능을 사용합니다. 기존 미신청 `1`은 조회나 자동 처리로 수정하지 않습니다.

좌석 저장은 **선택한 교시만 변경**합니다. 현재 교시 신청자는 체크하면 출석 `2`, 해제하면 결석 `3`입니다. 현재 교시 미신청자는 체크하면 `2`, 해제하면 기존 `2`/`3`도 빈 값으로 비웁니다. 사전 결석 `4`는 체크·전체 선택·저장 대상에서 제외되며 조회 후 새로 등록된 `4`도 서버에서 보호합니다. 각 변경은 감사 기록에 남습니다.

현재 교시에 저장된 `2`는 체크, `3`은 해제로 복원합니다. 미확정 신청자는 1교시에는 체크하며, 2·3교시에는 직전 교시의 **실제 저장값**이 `2`면 체크, `3`/`4`면 해제, 그 외에는 체크합니다. 현재 교시 미신청자의 미확정 상태는 이전 교시 값과 관계없이 해제입니다. 이전 교시의 미저장 체크는 이어받지 않습니다. 시간 경과나 저장 후 다음 교시로 자동 이동하지 않습니다.

좌석과 미신청자는 각각 자기 영역 전체를 한 번의 요청으로 저장하며 다른 영역의 초안은 그대로 둡니다. 날짜·교시 변경, 화면 새로고침, 로그아웃·메인 이동 시 미저장 좌석·미신청자·교사 입력 변경이나 결과 미확정 요청이 있으면 폐기 확인을 받습니다. 요청 처리 중에는 앱 내 이동을 막고 브라우저 새로고침·닫기는 가능한 범위에서 경고합니다. 교사 로그인은 한국 시간 자정에 만료됩니다. 학생 사전 결석과 자동 신청 처리는 기존처럼 신청 교시만 대상으로 합니다.

좌석 영역도 현재 교시의 수정 가능한 출결값이 `2` 또는 `3`이 아니면 기본 체크 상태가 바뀌지 않았어도 인원 요약에 `저장 필요`를 표시합니다. 사전 결석 `4`는 저장 필요 판단에서 제외합니다.

### 미신청자 목록

교사 화면에는 검색 결과와 처리 상태·오류를 표시하며, 검색 전 기본 안내와 미신청자 운영 규칙에 대한 상시 설명 문구는 표시하지 않습니다. 안내 문구 제거에 따른 설정이나 운영 절차 변경은 없습니다.
검색 결과는 학번과 이름만 표시되며, 해당 버튼을 누르면 체크된 새 로컬 행을 추가합니다. **저장을 누르기 전에는 서버에 기록하지 않습니다.** 이미 목록에 있는 학생은 중복 추가하지 않습니다.
조회 전용 목록은 실제 출결에 따라 출석은 초록색, 결석은 빨간색, 기록 없음은 흰색입니다. 오늘 편집 목록의 각 행은 저장된 상태와 저장 예정 상태가 다르면 `없음 → 출석`, `없음 → 결석`, `출석 → 결석`처럼 표시하고, 같으면 단일 상태명만 표시합니다. 현재 교시 출결값이 `2` 또는 `3`이 아니면 비어 있거나 `1`, `4`인 경우에도 기본 체크 상태가 바뀌지 않았어도 최초 저장이 필요하므로 상단 요약에 `저장 필요`를 표시합니다. 상단 요약은 `날짜 · N교시 - N명 (출석 N명) · 저장 필요` 형식이며 저장 필요 여부는 상단 요약에만 표시합니다.

좌석 아래에서 학번·이름을 검색해 오늘 참여 학생을 추가합니다. 정기 신청자도 추가할 수 있지만 **좌석과 목록은 별도 출결 기록**입니다. 정상 학생명단에 있는 학생만 검색되며 전화번호 형식 오류 등은 먼저 명단에서 수정합니다. 검색 명단은 현재 페이지 메모리에만 저장하므로 명단 변경 후에는 페이지를 새로고침합니다.

- 도구 모음은 **저장**, **전체 선택/전체 해제**, **모두 삭제**입니다. 저장은 새 행을 포함한 목록 전체를 한 요청으로 보내며 체크는 현재 교시 출석 `2`, 해제는 결석 `3`으로 기록합니다. 다른 교시와 좌석 출결은 변경하지 않습니다. 저장된 학생은 그날 모든 교시에 표시됩니다.
- 현재 교시의 저장값 `2`/`3`은 체크/해제로 복원합니다. 미확정이면 1교시는 체크, 2·3교시는 직전 교시의 저장값이 `3`일 때만 해제하고 그 외에는 체크합니다. 새 로컬 행은 항상 체크 상태로 시작합니다.
- 서버는 목록 전체를 먼저 검증합니다. 두 교사의 출결 변경은 마지막 저장 우선이며 출결값 변경만으로 충돌하지 않습니다. 누군가 행을 삭제했다면 삭제 세대 차이로 차단하여 오래된 저장 요청이 행을 되살리지 못하게 합니다. 모두 삭제는 확인한 목록 구성도 일치해야 합니다.
- **삭제 경고: 행의 삭제 버튼은 선택 날짜의 해당 학생과 1~3교시 출결을 모두 삭제합니다. 모두 삭제는 선택 날짜의 목록과 1~3교시 출결 전체를 삭제합니다.** 출결이 남아 있어도 삭제할 수 있습니다. 다른 날짜와 기존 감사 기록은 보존하며 `2`/`3`에서 빈 값으로 바뀐 이력도 남깁니다. 실행 전 확인 창에서 날짜와 삭제 범위를 확인하세요.
- 새 로컬 행의 삭제는 초안에서만 제거합니다. 저장된 한 행을 삭제해도 삭제 세대가 그대로인 다른 학생의 체크 변경과 새 행 초안은 보존합니다. 모두 삭제는 해당 날짜의 로컬 초안도 정리합니다.
- 응답 유실이나 오류로 결과를 확인하지 못하면 **저장 재시도** 또는 **삭제 재시도**를 사용합니다. 같은 UUID와 변경하지 않은 요청 내용으로 재시도하므로 중복 적용을 막습니다. **대기 취소 · 서버 다시 읽기**는 확인 후 초안을 버리고 최신 상태를 읽으며 이미 서버에 접수된 요청을 취소하지는 않습니다.
- 저장·삭제 중에는 목록 조작과 앱 내 이동이 제한됩니다. 결과 미확정 상태에서는 요청 내용을 바꾸지 말고 재시도하거나 폐기 확인 후 서버 상태를 다시 확인하세요.

`미신청자` 시트는 초기화 시 자동 생성됩니다. 실제 첫 저장 때 날짜당 4열을 시간순으로 생성하며 1행은 실제 날짜, 2행은 `학번 / 1교시 / 2교시 / 3교시`, 3행부터 학생 목록입니다. 날짜별 학번 목록은 독립적이고 같은 날짜에는 학번당 한 행입니다. 상태는 빈 값, 출석 `2`, 결석 `3`만 사용합니다. 미운영일로 변경해도 이 시트의 기록은 자동 삭제하지 않습니다.

`교사` 시트도 초기화 시 자동 생성됩니다. 1행은 `날짜 / 교사` 헤더이고 2행부터 날짜별 교사 정보를 저장합니다. 날짜는 실제 날짜값으로 관리합니다. 같은 날짜 행을 직접 여러 개 만들지 마세요. 중복되어도 웹 앱은 첫 번째 행만 수정합니다.

이름은 현재 학생명단에서 읽습니다. 명단 삭제·오류 시 `학생 정보 확인 불가`로 표시하고 출결은 보존합니다. `기록` 시트에서는 내부 키 `extra:학번`으로 구분하므로 학번을 다른 학생에게 재사용하지 않습니다. 학생 로그인 허용 범위는 종전 그대로이며, 이 목록에 추가했다고 학생 로그인이 새로 허용되지는 않습니다.

### 변경 후 운영 확인

요일별 좌석 정책 반영 시 기존에 같은 요일의 서로 다른 교시로 나누어 공유하던 좌석도 중복 오류가 됩니다. 배포 후 **시트 초기화 및 검사**에서 확인하고 아래 학생 정보 변경 절차에 따라 명부를 수정합니다. 기존 출결 데이터의 자동 변환이나 새 설정 추가는 없습니다. 다른 요일의 좌석 공유는 그대로 허용됩니다.

체크박스 UI 배포 시 운영자는 새 **`src/ExtraBatchService.gs`를 포함한 `src/` 전체**를 함께 반영합니다. 로컬 의존성은 `pnpm install`로 설치하며, 통상 검사는 `pnpm check`로 타입 검사·GS 린트·HTML 린트·포맷 상태를 확인합니다. `pnpm deploy`는 검사 후 `clasp push`를 수행합니다. 이어 Apps Script 웹 앱의 새 버전을 배포합니다. 이 절차는 운영자가 수행하는 배포 안내이며 문서 수정 작업 자체에서 검사나 배포를 실행할 필요는 없습니다. `.clasp.json`의 `rootDir`은 `src`로 유지하고 로컬 Script ID는 공개하거나 커밋하지 않습니다.

새 코드 반영 후 운영자가 **시트 초기화 및 검사**를 실행합니다. 이번 UI 변경에 새 필수 설정·Script Properties·트리거 또는 데이터 마이그레이션은 없습니다. 이미 열린 기존 클라이언트와 영속 요청을 위한 이전 API·복구 경로도 유지합니다. `EXTRA_` 속성은 요청 UUID, 완료 결과, 삭제 세대, 분할된 미완료 변경 의도를 자동 관리하므로 직접 삭제하지 않습니다. 미완료 저장은 다음 미신청자 요청에서 셀·기록을 대조해 중복 없이 복구합니다. 직접 시트 편집 등으로 복구할 수 없다는 오류가 나면 시트와 기록, 해당 미완료 속성을 백업하고 대조한 뒤 복구해야 합니다.

미신청자 배치는 최대 1,000명이며 속성당 9KB 제한을 피하도록 계획을 약 7,000바이트 단위로 나눕니다. 기존 메타데이터가 399,000바이트를 넘거나 배치 저장 여유를 포함한 예상량이 400,000바이트를 넘으면 `EXTRA_METADATA_FULL`로 중단합니다. 기존 요청 경로의 120,000바이트 메타데이터 및 8,000바이트 의도 제한도 유지합니다. 오늘·어제 완료 기록과 미완료 작업은 보존하고 오래된 항목만 자동 정리하므로 용량 오류를 피하려고 속성을 임의로 지우지 마세요.

배포 후 운영자는 `DETAILS.md` 17절에 따라 실제 웹 앱에서 초기 체크 규칙, 현재 미신청자의 해제 시 빈 값 저장, `4` 보호, 전체 선택 토글, 자동 교시 전환 없음, 영역별 독립 저장을 점검합니다. 미신청자 로컬 추가·일괄 저장, 응답 유실 재시도, 마지막 저장 우선과 삭제 세대 충돌, 1~3교시 삭제 경고·감사 기록 보존, 행 삭제 후 다른 초안 보존도 확인합니다. 날짜·교시·새로고침·로그아웃의 폐기 확인과 요청 중 이동 차단, 조회 전용 실제 색상과 편집 예정 색상, 학생 미래 결석 등록 유지도 확인합니다.

서버는 묶음 조회한 스냅샷을 재사용합니다. 좌석은 변경값별 `RangeList`로 최대 3회 쓰며 학생별 셀 `getValue()`를 호출하지 않습니다. 미신청자는 변경 행 구간의 날짜별 4열을 한 번 쓰고 감사 기록도 묶음 저장합니다. 중간 실패는 자동 롤백이 아니라 영속 요청 복구 대상으로 취급합니다.

## 학생 정보 변경

한번 사용한 명부 행의 학번은 직접 고치지 않습니다. 신청 정보 변경이 필요하면 기존 행의 C:N 신청값을 모두 비운 뒤 새 행을 추가합니다. 이름이나 전화번호 뒤 4자리를 바꿀 때는 `학생명단`을 수정하고 **학생 명단 적용**을 실행합니다. 신청값이 모두 빈 기존 행은 과거 출결 보관용으로 유지합니다.

### 기존 명부 전환

이전 구조의 `명부`는 자동 변환되지 않습니다. 스프레드시트를 먼저 백업한 뒤 B열의 이름과 D열의 전화번호 뒤 4자리를 `학생명단`으로 옮기고, 기존 B열과 D열을 직접 삭제해 새 열 구조에 맞춥니다. 이후 **학생 명단 적용**과 **시트 초기화 및 검사**를 차례로 실행합니다.

## 미운영일 관리

`설정` 시트에서 다음과 같이 입력합니다.

| 열 | 입력 내용 |
| --- | --- |
| A | 미운영 날짜 |
| B | 사유 |

A열은 텍스트가 아닌 실제 날짜값으로 입력합니다. 새로 등록한 미운영일은 학생의 결석 등록과 교사의 출결 대상에서 제외됩니다. 오늘부터 30일 후 사이에 이미 만들어진 `명부`의 해당 날짜 출결 열은 자동 처리 시 삭제되지만, 과거 출결 열과 `미신청자` 기록은 삭제되지 않습니다.

## 운영 시 주의사항

- 프로젝트와 스프레드시트의 시간대는 모두 `Asia/Seoul`로 유지합니다.
- 같은 요일에는 교시가 달라도 좌석번호가 겹치지 않도록 입력 후 **스공시 관리 → 시트 초기화 및 검사**를 실행합니다.
- 날짜별 출결 열과 숨겨진 내부 키는 직접 추가하거나 수정하지 않습니다.
- 날짜 제목에는 연도가 포함되므로 새해가 되어도 기존 출결 열을 삭제할 필요가 없습니다.
- 자료를 별도로 보관하려면 스프레드시트 전체를 복사합니다.
